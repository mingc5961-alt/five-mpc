## 4　E1　固定中心，只改变波束风险估计能读到的历史

### 4.1　如何做到“固定中心”

1. 对每个世界按 `grudata.schedule(w,41000+k)` 产生外生已购事件。在完成时刻 τ 读取一次 `w.observe(u,τ)`；记录完整带噪观测前缀。每个唯一前缀只调用一次 Chronos，签发 `c[21,3]`、原生角宽 `wc[21,2]`，网格 0、0.5、…、10 s。同步保存原生 factors；区分角宽、校准因子和实验倍率，以免重复缩放。
2. 键含 `split、namespace、world_sha、uid、n、完成时刻、prefix_sha、checkpoint_sha、GRID、dtype`。全部实验臂引用同一份中心数组和同一个真值寿命。签发后不因年龄增长再推理；用同一数组插值。完整签发窗口要求 τ+10≤180 s。对齐键时对照各臂行数、`center_sha`、逐行视线角误差和真实寿命，差异数必须为零。
3. 建立记忆时先结算本次付费观测能够验证的旧预测，再签发新预测。旧预测签发于 τ₀，只有本机后续已购观测在 τ₀+δ 到达且 0<δ≤10 s 时，才可用其带噪位置与旧中心在 δ 处的插值计算角残差。保留实际 δ、测量噪声和成熟时刻。用最近三笔组成当前短查询片段；旧匹配片段的结束时刻及被检索残差的成熟时刻，都须严格早于这三笔中第一笔的完成时刻。整份已付费历史仍是可见信息范围。真值轨迹、未来下一次付费时刻、人工重访和偏航标签只用于训练监督或事后分层。

### 4.2　对照矩阵

| 臂 | 对固定中心的风险估计 | 作用 |
|---|---|---|
| C-native | 原生 Chronos 角宽和原生 factors | 回归锚点与强预测器原生能力 |
| GEO | 最近两笔付费位置估速度；以恒速外推方向相对同一 Chronos 指向的偏离估计 3 dB 边界，按网格取允许档位。首笔时采用预先冻结的公共回退 | 低成本位置、速度与波束边界对照 |
| C-cal | 共同特征含原生角宽、预测期限、当前位置/距离、观测数、最近定位间隔、测量协方差；配同规格新校准头 | 单独估计重新校准的贡献 |
| TIME | C-cal 加同机历史窗口检索。仅按近期相对运动序列相似度取过去已成熟残差 | 通用时间序列检索基线，按项目观测权限适配 |
| ROUTE | 在 TIME 的信息与同一历史池上加入空间位置、历史航向和沿航段形状匹配，选出旧航段；加入残差分布、匹配距离、航向差、有效邻居数 | 主方案，检验地理对应关系的增量 |
| SHUFFLE | 保持 ROUTE 架构和每个前缀可见的已成熟记录数，将旧空间键和旧片段结果在该机合格历史池内配错；固定随机种子。训练、校准、评估均按同一负对照协议 | 判断增益是否来自正确的路线对应，而非多一组输入或非空记忆 |

TIME 与 ROUTE 使用同一窗口长度、候选时间跨度、最多邻居数、残差统计维度和计算预算。首版用最近 3 笔形成查询，最多检索 3 个邻居；候选网格、距离归一化和分数阈值在开发阶段锁定。对 TIME 屏蔽绝对坐标作为**检索键**，共同校准特征仍与 ROUTE 相同。SHUFFLE 保留时间残差分支，只置换空间分支的对应关系；单一候选无法打乱，记录有效置换比例。没有已成熟时间邻居时，各检索臂直接继承 C-cal 的最终输出；有时间邻居但缺少合格空间支持时，ROUTE 和 SHUFFLE 直接继承 TIME 的最终输出，逐行核验。报告两级回退占比。ROUTE 不读测试线路 ID。

实现首版可沿用 `paired_models.fit` 的 0.90 分位 LightGBM（110 棵树、12 叶、seed 7），训练目标为相同中心的绝对角残差取对数；学习臂使用相同容量、世界和调参次数。每个校准世界选同一个预冻结锚点，使用 20 ms 轴上整段最大标准化角误差得到各期限校准因子，复用原 `tube.scores` 口径。独立校准后统一比较倍率 **0.75**。另在开发集冻结风险匹配工作点作敏感性结果。0.90 是模型分位目标，7% 是另行验证的闭环链路风险。

### 4.3　寿命、主比较和验收

主阵列为 **32×32**。从签发时刻沿同一 Chronos 中心指向，以 20 ms 重放。首次阵列增益相对对准时下降超过 **3 dB**，按原 `life` 取前一格为最后安全时刻；起点即越界记 0。10 s 内未越界记右删失，在本实验的 **10 s 限制性寿命** 中取 10 s，该样本参与所有限制性秒数的计算。各头对同一中心按原 `worst_losses`、单调前缀准入规则，从 0、0.5、1、2、3、5、8、10 s 中签发寿命。原 `life` 写死 0.75 和 32×32，参数化时用原默认做逐行回归。

主查询预登记为同向重访、已付费次数 `n∈{6,8,12,24,40}`、年龄 `a∈{2,3,5}s`、额外期限 `h=0`。同一前缀的预测寿命和真实寿命分别减去年龄并截零，得 A 和 L。记录过度准入 O=max(A−L,0) 与错失可用 U=max(L−A,0)，单位均为秒。分层同时报告全查询、首访、低复用、偏航/重入、有无可用历史；`natural` 仅作事后敏感性分析。原面板的 `h=2` 行共享寿命，主分析只计一次。

**主比较为 ROUTE 对 TIME。** 建议预登记双判据：`U_TIME−U_ROUTE` 的 95% 配对区间下界 >0，且 `O_ROUTE−O_TIME` 的上界 <0.02 s。0.02 s 是本方案建议的一格风险非劣界，须在首次看新确认结果前冻结，并单列零容忍敏感性结果。对开发时冻结的最强非空间学习臂再做同一对照。路线归因还要求 ROUTE 相对 SHUFFLE 沿同一双判据获益、且有足够可置换样本；否则只能写“带检索特征的风险头改善了保持期判断”。两臂均极保守或某些层无有效世界时，报出短板及区间。

## 5　E2　同一张 849 次预约表，只改变“这次买给谁”

### 5.1　预约表与选人接口

从 `T/aoi_reference.py` 调用 `QuotaGrid(service_us=180000000,budget_us=3000000,fix_us=3100,users=16,quota=849)`。必须显式写 `quota=849`，默认值是 854。967 个候选机会相隔 186,000 µs；对 `fixed_indices()` 返回的每个 i，取 `[start_us(i), start_us(i)+3100]`。主比较各臂**逐笔复用实际开始与完成时刻**。前 16 笔依次给 uid 0…15，后 833 笔才选择对象。每场每臂实付 **2.6319 s**，预算上限为 3 s。

随包 `calendar_849.json` 以无空格、无换行的紧凑 ASCII JSON 保存 `[[start_us,end_us],…]`。SHA-256 应为 `2f55c7e415f074bcdce383830d90f9d1f2f36e58ba3adf76ca6c7094929bc32c`。第 1、16、17、849 笔分别为 `[0,3100]`、`[2790000,2793100]`、`[2976000,2979100]`、`[179676000,179679100]`。服务器由原函数重新生成并比对全集。

在预约开始前，策略只读各机截至该时刻已收到的定位、上次签发的中心和风险、当前已知动作/剩余寿命，以及公开时钟。选定唯一 uid 后再调用原 `purchase(uid,start)`，到完成时取 `w.observe(uid,end)` 并更新该机。各臂共享同一物理世界和噪声场；若世界、用户和完成时间相同，观测必须相同。分歧之后各臂按自己的付费历史生成 Chronos 中心，缓存也要包含完整前缀哈希。直接强制不同历史给出相同中心会破坏闭环。

**所有臂购后服务均采用原生 Chronos 中心、角宽、factors、共同倍率 0.75、同一个码本、MCS 和服务分配器。** E1 路线头只进入选人器。每个实验臂只能更改本笔 uid，不能改变购后波束控制器的版本或预约次数。选择改变未来信息、波束和交付比特，正是本实验要计入的效应。

### 5.3　价值头的可实现训练目标

1. 在训练世界的固定预约上，用 EDF 与随机合法选人的混合采集付费状态，覆盖不同年龄、风险和剩余配额。候选与标签都以同一个决策前状态为单位。初版可取 32 个训练世界、每世界 8 个初始化后且窗口完整的预约、每预约全部 16 个候选，共 **4,096 个短分支**。选择种子、采样分布与开发扩展条件写入草案。
2. 对每个候选 j，在本预约仅将定位给 j。各分支随后沿同一张日历，用共同、冻结的 Chronos EDF-native 继续策略从各自状态因果运行。取从当前预约开始至第 24 个候选机会间隔末端的全机群交付比特（24×0.186=4.464 s，完整窗口才采样）。同一状态下各候选比特减去其候选均值作为监督标签；差值衡量固定本笔及未来配额下选 j 的短窗价值。数据时长、定位和切换均由同一账本一次核算。
3. 先实现慢速参考：固定同一历史前缀，分支重放后用 `policy_env.trace` 对齐原时钟分窗；再实现状态复制/快照加速。快照应含最近中心、付费历史、调度动作、令牌桶、账本状态和随机状态。抽几个世界、时刻及候选，对比重放与快照的事件、分窗交付比特和故障数。账本全窗比特重组误差沿用 `trace` 的 ≤1 bit 界。
4. 用同一规格的轻量回归器拟合候选分值，首版用固定容量 LightGBM。共同输入可含 AoI、预计角度方差、当前波束/期限、预测位置下的服务速率及公共候选状态汇总；空间历史只通过预登记的路线特征/风险头进入 VALUE-route。两个价值头各自在同一训练样本上拟合，调参次数相同。决策时只能从上述只读视图算分；仿真反事实和已交付真值均不进入在线得分。报告 held-out 开发状态上的排序质量和对 EDF 的平均短窗后悔值，用于诊断。

### 5.4　逐场硬验收与主比较

- 逐笔核对完整 `start_us/end_us` 序列、时钟 SHA、初始化 uid、849 笔实际成功、定位占时 2.6319 s。另存含 uid 的事件 SHA，允许它随方法改变。原 `P01/P02/P03` 验证固定时刻，`Q08` 是联合时钟的 Chronos 对照，不能直接充作本次端点。
- 所有臂共用物理指纹和购后控制代码指纹。四项无线时长和为 180 s（容差 1e−6 s），定位账本误差 <1e−7 s，16 架各 9,000 个探针；`sum(bits)/(180×10⁶)` 与 `G_mbps` 差 <1e−6。做“同一规则走旧入口与新回调”的事件、账本及结果回归。
- 主指标为 G（Mbps）、R（所有用户探针中不可用或指向损失 >3 dB 的百分比）。拆分两种风险时均使用**全体探针**作分母。另报有效窄束通信秒、16 用户吞吐的第 5 百分位、Jain、每机最大定位空窗、各机购买数。可将配对差 `ΔG×180×10⁶/849` 报作平均每笔预算对应的新增比特。
- **路线主对照**为 VALUE-route − VALUE-time。**先进性对照**在开发集按同风险规则从无空间路线臂中冻结最强者，并在确认集和它作配对；**简化对照**为 VALUE-route − EDF-route。主成功条件为 `LCB95(ΔG)>0` 且 `UCB95(ΔR)<+0.5 个百分点`。如宣称满足绝对 7% 目标，还须本臂 `UCB95(R)≤7%`。若共同倍率未满足 7%，另外展示预先在开发集选定的同风险工作点和可行范围，分别标明。
- 比较集也要冻结。E1 的非空间学习臂按开发集共同过度准入上限（取 TIME 在 0.75 的均值）下最小 U 选出；确定性并列按较小 O 再按固定臂名字典序。E2 在开发集 0.75 下，从 MAXAGE、AoI-DQN-fixed、VAR、EDF-native、EDF-time、VALUE-time 中选 R≤7% 且 G 最大者；无人达标取 R 最低，再取 G 较大者。另行风险匹配时各臂用相同的倍率网格与选择规则，只比较有共同可达风险的区间。对“胜过全部对手”的措辞，需确认全部相应配对都支持；开发选定强对手的成功只支持针对该对手的结论。
- 逐笔记录 `calendar_idx、uid、pre_history_sha、各候选 score、AoI、deadline、支持度、tie、回退、service_model_sha`。在同一因果状态对不同规则“只打分”，专门分析 AoI 接近但排序不同的冲突预约。跨臂运行后期各自的状态不同，不能直接拿两份独立轨迹上的分数当同状态排名。

## 6　执行、算力与回执

以下是**服务器 Codex 要实现的 CLI 契约**。当前归档已有第 1 节的两条核验命令。进入映射后的 `I` 工作副本，设置 `OUT` 为新产物根；将随包 `protocol.json` 和 `calendar_849.json` 放入该根。建议依次执行：

```bash
python chronos_849.py preflight --out "$OUT"
python chronos_849.py smoke --out "$OUT" --world 1400
python chronos_849.py fit-life --out "$OUT"
python chronos_849.py fit-value --out "$OUT"
python chronos_849.py develop --out "$OUT"
python chronos_849.py freeze --out "$OUT"
python chronos_849.py confirm --out "$OUT" --experiment E1
python chronos_849.py confirm --out "$OUT" --experiment E2
python chronos_849.py report --out "$OUT"
```

| 阶段 | 首批任务与通过条件 |
|---|---|
| 预检与 smoke | 重放旧开发锚点，加载校验后的 Chronos；固定事件走两条入口结果一致；E1 同一前缀中心与逐行角误差相同；E2 日历与随包文件完全相同。对时间戳越界、伪造未购观测和缓存混用加回归检查。记录缓存命中、每千前缀前向耗时、单世界闭环时间和峰值内存。 |
| 拟合与开发 | 构造 E1 风险头和校准件，生成 E2 标签并拟合价值头；跑全臂、预先列出的同规格倍率网格（可用 0.45、0.60、0.75、1.00）。按实测吞吐量决定并发和缓存策略。若分支成本高，优先缓存共有前缀与共用世界，再在开发阶段调整训练状态数；成对臂共享同一标签集。 |
| 冻结 | 保存 `design/frozen.json`、完整世界列表和输入指纹、时钟、校准件、学习种子、共同及风险匹配工作点、统计与作图配置、期望端点索引。检验训练/校准/开发与确认物理指纹不交叉。 |
| 新世界确认 | E1 每世界生成一份公共前缀面板，派生六臂评分。E2 八个选人臂，其中一个固定 DQN 可沿用三个冻结种子；按 48 世界、其余确定性臂各一次计，共同倍率为 **480 个闭环端点**。其他预冻结倍率独立计数并去重。预计墙钟用 smoke 实测的单世界耗时×端点数÷实际并发估算，开发、反事实分支和正式端点分别记账。 |
| 汇总 | 每个工作单元输出原子回执。断点续跑检查版本、前缀/世界 SHA 和设计哈希；样本或端点缺失时显式列出，不做无说明的删行。输出两组结论，即使其中之一未过线。 |

要求至少交付 `manifest.json`、`design/frozen.json`、`E1/prefix_index`、`E1/scores`、`E1/calibration`、`E2/calendar_849.json`、`E2/receipts`、`E2/decision_logs`、`audits.json`、`world_scores.csv`、`contrasts.csv`、`figures/` 和 `REPORT.md`。逐前缀与逐笔大表可压缩分片，引用路径与 SHA。所有图表均能从同批冻结回执重建。
