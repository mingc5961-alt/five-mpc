# GRU 路线门控对微调 Chronos‑2 原生管的等风险闭环复刻

**目标行**为原四组闭环实验的 `split=confirm, case=irregular, mode=closest_to_native`。在两个新种子平均风险 **4.505208333%** 下，按角误差选出的 GRU 门控比未缩放的微调 Chronos‑2 **多 162.726428 Mbps（+15.28%）和 3.831038 秒有效窄束服务（+15.40%）**。本次只涉及原来的 **10/16 架无可复用路线**确认集。独立世界数为 2。

## 1. 在 Linux CPU 服务器执行

下载随文的 `gru-chronos-4505-cpu.tar.gz`。包内有原始仿真与调度代码、冻结模型、专用管、Chronos 本地快照、32 份参考回执和单一运行入口。模型可以离线加载。建议解压到新的可写工作目录，以便区分新生成和历史参考的回执。

```bash
tar -xzf gru-chronos-4505-cpu.tar.gz
cd gru4505
python3.12 -m venv .venv
source .venv/bin/activate
python replay.py check
python -m pip install --index-url https://download.pytorch.org/whl/cpu 'torch==2.15.0'
python -m pip install -r requirements-replay.txt
python -m pip check
python replay.py reference
python replay.py six --workers 4
```

| 命令 | 会做什么 | 用来验收什么 |
|---|---|---|
| `python replay.py check` | 仅用 Python 标准库，逐文件检查包内 SHA‑256 | 模型、配置、代码和参考回执的字节一致性 |
| `python replay.py reference` | 对独立目录 `reference/` 中的原始 32 份回执重新算表 | 先验证统计口径；该命令不运行模型 |
| `python replay.py six --workers 4` | 生成两个确认世界，各跑 Chronos 1.00、GRU 0.55 和 0.75，共 6 个完整闭环 | 从物理仿真到两项正增益 |
| `python replay.py common --workers 4` | 用相同场景重建五种方法的全部实测曲线，合计 32 个独立配置回合；已有的 6 个会复用 | **完整复刻“共同风险，取最靠近未缩放 Chronos 的可达值”** |
| `python replay.py score-six` / `score-common` | 只对服务器本次产生的回执重新算表 | 核对断点续跑或拷贝的结果 |

**原问题的完整验收命令是 `common`。** 可跳过 `six` 直接执行 `common`。服务器输出在 `experiment/gate/fusion/closed/runs/`，预热状态在同级 `warm/`。二者均从空目录起步，程序按已完成的回执续跑。`reference/` 单独保存，真实重放不会从该目录补结果。同时改变模型、种子或参数做扩展时，另解压一份，避免沿用旧缓存。

原运行环境为 Windows CPU、Python 3.12.14、PyTorch 2.15.0+cpu、chronos-forecasting 2.3.2、Transformers 5.22.2、NumPy 2.5.4、LightGBM 4.7.0，其他主要版本见 `requirements-replay.txt`。以上安装命令对应这些版本，服务器需能访问相应 Python 轮包或使用已备好的离线镜像。对 24 核 / 45 GB 的服务器，4 个单算子线程的工作进程是保守起点，可直接在 CPU 上执行。原来截图中的 PyTorch 2.10.0 属于另一套环境；如使用该环境，应记录实际版本并按第 5 节逐端点核对。运行入口自动定位包内资源，无需配置 Windows 盘符或 Hugging Face 账号。

## 3. 冻结模型和误差管

**GRU 角误差组 `Gangle = arm G, profile 1`。** 每次发布只读最近 8 秒观测。每个 1 秒槽有 7 项输入，即三轴位移、观测间隔、径向速度、定位协方差迹的 `log1p` 和径向速度标准差，另加有效掩码。按检查点中的均值/标准差归一化并截断至 ±6。每两槽拼成一个 16 维 token，线性投影至 24 维后进入单层 24 维 GRU。LayerNorm 和线性头输出 20×3 个 IMM 位移修正，得到 0.5–10 秒的短期专家中心。长期专家为从该机截至发布时的观测持续更新的路线记忆。

融合中心为 `short + w × (route − short)`。在 1、2、5、10 秒的基础路线权重为 `[0.25, 0.25, 0.35, 0.50]`，已兑现误差的半衰期为 `15 + 1.5 × 预测期限` 秒，`kappa=0.3`、反馈强度 1。按期限更新权重后，profile 1 再叠加 `[0, 0, +0.05, +0.10]`，其他期限线性插值，最终裁剪到 [0,1]。该 profile 是在开发集上按四期限角误差等权选出，确认时保持冻结。管宽倍率仅缩放预测半宽。

**GRU 专用误差管**读取 `closed/tubes/G1.pkl` 的 `tree` 和 `final`。训练使用 24 个独立单机世界、1031 个发布起点；LightGBM 对数绝对角误差分位数回归，`alpha=.9, n_estimators=110, num_leaves=12, min_child_samples=85, learning_rate=.055, random_state=7`。候选校准、最终校准各用独立的 40 个世界，审计另用 32 个。按每个期限双角全前缀最大标准化误差取 40 个值中的第 37 个并施加单调约束。七个期限的最终因子约为 `[1.04258528, 1.28645789, 1.33106177, 1.50409498, 1.66745191, 1.73435783, 1.73435783]`。该模型的离线标称覆盖率 90% 和闭环 4.505208% 总风险各有独立定义。

**Chronos 对照 `C = arm C, profile 0`。** 用本地 Chronos‑2 快照 `29ec3766d36d6f73f0696f85560a422f50e8498c` 构造模型，加载原实验训练种子 **7** 的 `training/Chronos-2/7/best.pt`。读取截至发布时最近 180 秒坐标，0.5 秒间隔、360 个带掩码历史槽，以最后一次观测为坐标原点；三轴分组推理、两个输出 patch，采用 0.1/0.5/0.9 分位数。误差管读取 `tubes/Chronos-2/7/bundle.pkl["factors"]["native"]`，主对照额外倍率严格为 **1.00**。训练种子 7 与测试航迹种子 0、1 分工不同。

## 4. 如何重建“最靠近未缩放 Chronos 的共同风险”

1. 每个管宽倍率都分别在种子 0、1 跑完整回合，先对两个世界的风险、净吞吐等指标等权取平均，得到该倍率的端点。
2. 五种方法为 C、Gangle、Gnet、Iangle、Inet。C 的实测倍率为 **0.35、0.55、0.75、1.00**。门控方法均为 **0.55、0.75、0.90、1.00**。Gangle 和 Gnet 分别是 G1 和 G0；Iangle 和 Inet 共用 I1 的回执。因此有四条不同曲线，合计 **4 × 4 × 2 = 32** 个回合。
3. 每条曲线可按整回合概率混合任意两个实测端点。各方法的风险上下界取所有倍率的最小、最大实测风险。其共同区间为 **[4.284722222%, 5.871527778%]**。将未缩放 Chronos 的平均风险裁剪到此区间，本场景得到原值 **4.505208333%**。
4. 在该目标上，对每组枚举能精确达到目标的单点和两点混合，取期望吞吐最高者。`closest_to_native` 在目标等于未缩放 Chronos 风险时，固定 C 为 1.00。对 GRU，0.55 倍和 0.75 倍的平均风险分别是 **6.009375%**、**3.945486111%**，从而有

   `P(m=0.55) = (4.505208333 − 3.945486111) / (6.009375 − 3.945486111) = 0.27119784656796747`
   `P(m=0.75) = 0.7288021534320326`。

5. 把同一对概率作用到两个种子的全部指标，再等权汇总。验收时直接对实测回合做期望加权；随机抽两次倍率、每个时隙切倍率或把两个倍率平均成一个标量都会改变结果。这里的等风险是**确认集上的平均期望风险**，单种子的风险允许不同。

逐种子核验：种子 0 的 GRU 混合风险为 4.202288%，吞吐和窄束相对 Chronos 为 **+149.12 Mbps、+0.77 秒**；种子 1 为 4.808129%、**+176.34 Mbps、+6.89 秒**。对每个种子，各方法的预热观测 SHA‑256 必须一致。种子 0 应为 `4e5293c2b36d0cf51b83e445e753825265e88dd8a3733d691f9d07a98e8a4fe2`，种子 1 应为 `997bc62a5f5c31ba8277575751819caa833da0e0b7724dc5d4d0de55c4bc6fe4`。若输出有差异，先看指纹，再检查原始六个端点、误差管哈希、无线门限偏移与依赖版本；最后检查两个倍率的混合概率。表格对原值做了显示舍入。

**对照口径也可作验收。** 在相同 4.505208333% 风险下改用 `symmetric_near_native`，Chronos 也可选倍率，以 0.8614398422 概率用 0.55 倍、余下用 0.75 倍，得到 **1314.007246 Mbps、64.732255 秒**。同一个 Gangle 此时相对 Chronos 为 **−86.57 Mbps、−36.03 秒**。这说明 +162.73 Mbps 对应的是未缩放原生管基线。若要检验对未知航迹的迁移，应保留上述概率不动，另给独立命名空间并报告实测风险。

原始结果定位在 `四组闭环/确认结果.csv`、`逐世界配对.csv` 和 `runs/confirm_irregular_*.json`。包内 `replay.py` 只编排原运行入口、定位资源与验收；世界、模型、调度、计费及曲线混合复用原实验代码。
