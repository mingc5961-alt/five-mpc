## 1 同等波束稳定性下 F 与 RC 的吞吐比较

### 主指标与判定

- 主指标为**同一绝对时钟、逐机探测网格上的几何不稳定时间比例**。对服务窗中每架机使用同一组预定探测时刻。若当时没有可执行指向，或当前波束相对同阵列完美对准的增益损失超过 3 dB，记一个不稳定样本。公共探测网格仅用于评分，采样和分配过程没有新增空口动作。正常 TDMA 空闲仍可评估该机当前配置的波束。若选择到期回退，则所有方法的回退规则相同，并按回退后的实际动作评分。
- 报告实际数据机会内的超 3 dB、无可用波束时长、连续不稳时长和逐机尾部指标。保留第六章的任一采样越界即失效的保持段指标，供老表复核。它随分段长短改变，适合作为次指标。链路掉线、BLER 或基于速率门限的失效另行定义，来自批注的速率门限建议可放入信道敏感性实验。
- 在开发阶段确定具有业务含义的风险目标和等效容差 `epsilon`。0.2 个百分点可以作为讨论起点，须结合风险量级、业务和验证方差固定。主要确认点只选一个，先在验证世界固定。测试用世界级配对区间。可选 TOST 口径为稳定性差 RC−F 的 90% 双侧区间完全落在 ±epsilon 内，且配对净吞吐差 RC−F 的 95% 双侧区间下界大于 0。若还要宣称满足某个共同上限，检查各自风险的单侧上界。预先确定风险目标、误差区间、等效容差、分析单位和多工况处理。
- 吞吐为总期望交付比特除以整个服务窗，包含感知、切换、等待、回退和因延迟导致的损失。共享相同预算上限，实际感知占用是要测出的结果。世界配对固定初始历史、轨迹、外部噪声、信道、数据轮询和 MCS 策略。每个方法只有自身历史可见。测试集不参与选择工作点。

### F 与 RC 怎样各自选型

1. F 保留固定子阵列和固定刷新周期。它仍以因果 IMM 持续更新指向。按预算筛掉 `N*c/T > rho` 的组合，完整搜索 9 个子阵列 × 可行周期。在 16 机、3.1 ms / 1.667% 处现有网格有 36 个可行组合。复用 `tools/fixed_grid.py` 的快速枚举，补统一的稳定性结算和逐世界结果，抽样用正式事件仿真交叉核对。单纯吞吐优胜的 F 保留为历史参考。
2. RC 固定 G1 中心遍历少量事先定义的风险控制设置，例如按期限校准的包络放大系数和最长允许期限。IMM、P、RC 的误差头各自在相同开发权限和口径下独立选择。多组阈值先画验证风险与净吞吐前沿，再选两边均有实际支持的风险带。同风险带内各自取验证吞吐最高的策略，锁定后在新世界上重跑。
3. 主图画两条实测风险—净吞吐前沿及主工作点的区间。若两边都低于一个阈值而风险差未通过等效检验，结论写为“共同稳定性上限下的吞吐比较”。若没有共同支持，报告前沿和无等效点。主结果用可执行的固定配置点，不靠测试集挑选、曲线插值或临时混合策略。测试中若 F 更高、区间含零或 RC 风险不等效，如实报告。

## 2 预测器自带误差分数

### 统一的输出和动作接口

1. 每个预测器收到因果位置、可用的物理状态观测、时间间隔和缺测标记。邻机交互模型只看邻机截至发布时的可观测记录。路线协变量有明确的独立对照，仅使用此前观测生成的预测。过去状态在固定时钟上采用因果重采样，预测后对齐同一组 0.5–10 s 时域。位置中心和误差源一并入预测包。
2. **有原生概率输出的模型**保留分位数、分布参数或联合轨迹样本。Chronos-2 先保留各轴 q10/q50/q90，q50 给中心，分位距经角度投影给每个时刻的双轴尺度。可先用角度雅可比把位置尺度变成两轴角尺度，保持一个小的尺度下限，并在独立集用真实角度残差校准。笛卡尔边际分位数不解释为三轴或全时段联合概率。有联合轨迹样本的模型可把同一条样本轨迹转换到角域，在模型指标中直接计算期限内的联合误差。逐时逐轴独立抽边际分位数不可替代联合样本。
3. **确定性模型**在自身隐藏特征上增加方位和俯仰误差分位数头，输出随样本与时域变化的正尺度。优先用 `pinball loss` 拟合中心预测对应的绝对角残差分位数。用训练路线按组交叉拟合得到样本外中心残差，或冻结中心后用独立开发折训练误差头。线性模型可用自己的时域线性分位数分支。概率预训练权重冻结时，标注“冻结主干 + 目标域校准”；原本只做点预测的模型增加误差头后标注“目标域监督适配”。测试时只输出预测误差分数。事后真值用于训练、校准和评分。
4. 对每个模型和候选期限 Delta，从校准集对 `max_{h<=Delta, axis}(实际角误差 / 模型预测尺度)` 求目标分位的乘子。乘回每个 h 的双轴尺度，得全前缀误差包络。完整轨迹样本也可按同一个样本外前缀覆盖协议校准。各臂共享校准算法、样本数量和目标覆盖口径，各自估计系数。先报告整段联合覆盖和包络宽度，再报告调度实际选中期限的条件覆盖。尤其复核 8 s / 10 s。样本不足时可预先合并长时域或用保守回退，同时披露适用范围。
5. `scheduler.frontier` 对每档波束和每个候选期限检查整段联合增益损失上界。某波束满足目标的最大期限，给出可复用时长，由共享 value 调度器在可行集合内选择动作。同一中心下增加“模型自己的动态误差尺度、该模型固定按时域尺度、旧共用规格”的诊断，检验新误差分数是否真的改变候选宽度、期限与净吞吐。主表用模型自己的误差分数。同中心和共用规格对照放机制表或附录。
6. 明确区分**请求刷新时刻**与**可执行截止时刻**。固定实际失效回退规则，对所有模型一视同仁。预热、执行和 MCS 口径统一。线上记录中心推理、误差头、数据搬运、候选与排队的 p50/p95/p99。延迟较大者在回灌的闭环中按实际可用时刻发布，并按剩余时域选择动作。

归档 `ChronosAdapter.predict_inputs()` 已取 q10/q50/q90，将它们压成中心和对角协方差。先保留原生分位数用于控制，足以在尽量少改动的情况下复核当前 82.38% 紧预算覆盖问题。CR-G 复用已有 `CR` 框架，接通第六章入口后用同结构 G1 门控，独立训练融合后误差头或分布校准。比较 `C-native`、`CR_raw-native`、`CR-G-native` 与 RC，分别看路线协变量和门控。融合后的误差按融合输出重新估计，不能用两套分位数直接按相同权重相加。当前 CR 的基础路径已存在，但第六章的脚本入口没有 `CR` 选项。可在验证阶段将“有路线协变量”和“无路线协变量”的 Chronos 门控分开作为补充，避免过度归因。

代码入口为 [Chronos 分位数](../第二次完整结果/routeclock_archives/paired600/routeclock/foundation.py#L84)、[现有按期限校准](../第二次完整结果/routeclock_archives/paired600/routeclock/validity.py#L62)、[波束与期限候选](../第二次完整结果/routeclock_archives/paired600/routeclock/scheduler.py#L12) 和 [第六章可运行方法](../第二次完整结果/routeclock_archives/paired600/tools/ch6_experiment.py#L68)。

## 3 模型实现与选择

| 模型 | 原模型怎样实现 | 接 RouteClock 的方法与优先级 |
| --- | --- | --- |
| Chronos-2 / CR-G | 预训练 Transformer 直接输出多时域分位数，支持多变量与协变量。CR-G 是本项目将路线协变量 Chronos 专家与 IMM 门控融合的对照。 | **必跑**。尽量复用归档权重与现有输入，先跑自带分位数的 C 和 CR_raw，再给 CR-G 校准融合误差。 [官方实现](https://github.com/amazon-science/chronos-forecasting) |
| Chronos-Bolt | 将历史切 patch，经编码器与解码器直接输出未来分位数。 | **备选轻量同家族**。逐轴冻结推理并校准，作为成本下限，对复杂协变量的可见性按接口注明。 [官方模型实现](https://github.com/amazon-science/chronos-forecasting/blob/main/src/chronos/chronos_bolt.py) |
| Moirai-2 | decoder-only 时间序列 Transformer，当前官方 Moirai-2 实现直接产生分位数。 | **第一轮异家族基础模型**。用 Small 权重验证实际输入支持，保留多轴分位数并做统一前缀校准。当模型接口只支持部分观测通道时，提供公共输入子集结果。 [模型卡](https://huggingface.co/Salesforce/moirai-2.0-R-small) · [分位预测代码](https://github.com/SalesforceAIResearch/uni2ts/blob/main/src/uni2ts/model/moirai2/forecast.py) |
| TimesFM | patch 化的时序 Transformer。2.5 可启用分位头，官方 3.0 实例提供多变量、协变量与分位数。 | **Moirai-2 的替代或第二个基础模型**。锁定检查点和版本。3.0 若通过实际输入与延迟测试，适合对照多变量。2.5 可先用逐轴模式。 [官方实现](https://github.com/google-research/timesfm) |
| TinyTimeMixer | 以轻量 MLP Mixer 混合 patch、特征和可选通道。该轮候选检查点以点预测为主。 | **后置**。低成本值得观察，但先核对检查点的上下文长度和频率适用性。进闭环需加自己的误差头，按监督适配报告。 [官方模型卡](https://huggingface.co/ibm-granite/granite-timeseries-ttm-r2) |
| Lag-Llama | 把过去的滞后项输入 decoder-only 模型，自回归预测概率分布，官方可采样。 | **后置**。对各轴边际样本做误差尺度校准。多步采样的在线成本和轴间相关处理比直接分位模型繁复。 [官方实现](https://github.com/time-series-foundation-models/lag-llama) |
| FlightBERT++ | Transformer 编解码器用各预测期限的上下文一次性预测，进阶正式代码以差分 Gray 码表示连续飞行属性。 | **第二轮**。在本域重设 ENU 增量的编码范围和量化步长，用其隐层训练双角误差头。码位信心与定位误差分数需要独立映射。民航预训练情景的时标和尺度需重验。 [原论文](https://arxiv.org/abs/2305.01658) · [作者代码](https://github.com/gdy-scu/FlightBERT_PP_V2) |
| TrajAirNet | TCN 编码历史，CNN 编码风场，图注意力聚合邻机，CVAE 采样未来加速度，Verlet 积分生成轨迹。 | **多机交互场景再做**。RouteClock 目前的运动生成没有显式避碰互动，模型的邻机分支很难公平发挥。若接入，按可用通道裁剪并用完整路径样本打分。 [原论文](https://arxiv.org/abs/2109.15158) · [官方实现](https://github.com/castacks/trajairnet) |
| Trajectron++ | 异质动态场景图结合 CVAE、多模态轨迹分布以及类型相关运动学。 | **多机交互场景再做**。需要改成三维空中运动学和因果邻机图。采样空间路径后统一转为角误差。路网训练权重只作为方法参考。 [官方实现](https://github.com/StanfordASL/Trajectron-plus-plus) |
| UAV 专用模型，建议选 VECTOR | 用历史速度驱动 GRU 做三维多时域预测。第七章的“近期 4D UAV 模型”是一类方法，VECTOR 是此处新增的具体选择。 | **第一轮任务专用基线**。以同样可见的观测推得速度，按本域时间网格训练中心，在 GRU 隐层加模型自己的双角误差头。 [论文](https://www.mdpi.com/2504-446X/9/1/8) · [官方实现](https://github.com/mzahana/drone_path_predictor_ros) |
| iTransformer | 将每个变量的一段历史编码成 token，注意力在变量之间工作。 | **首选有监督时序诊断**。三轴和因果状态通道联合建模，接独立的期限误差分位头。保持输入历史和参数规模可对照。 [官方实现](https://github.com/thuml/iTransformer) |
| PatchTST | 将每轴时间历史切 patch，以共享编码权重做通道独立预测。 | **iTransformer 的备选**。用输出 latent 接双角分位数头。先比较对短、不规则历史的适配。 [官方实现](https://github.com/yuqinie98/PatchTST) |
| DLinear | 滑动平均分解趋势和余项，分别线性映射到未来，再相加。 | **低成本下限**。训练快，适合检查复杂模型的必要性。给各自线性分位数分支，或按验证选择是否进入闭环。 [官方实现](https://github.com/cure-lab/LTSF-Linear) |
| N-HiTS | 多尺度池化、残差 MLP 与层级插值重建未来。 | **备选单变量基线**。复用其分位损失接口，也可按固定版本加角误差头。优先级低于任务更匹配的 VECTOR 和 iTransformer。 [官方文档](https://nixtlaverse.nixtla.io/neuralforecast/models.nhits.html) |

先打通 Chronos-2 / CR-G、VECTOR 和 Moirai-2。DLinear 作低成本离线下限，若要测多变量监督架构，再加 iTransformer。一阶段最多让两个新模型进入闭环。若单一模型或算力环境不合适，以 TimesFM 或 PatchTST 替代对应家族，避免逐个堆叠模型。模型进入闭环看同覆盖目标下的整段包络宽度、窄束候选可行率、5–10 秒角误差和 p95 时延，指标与筛选规则事先写定。

## 4 数据取舍和采集口径

| 候选 | 定下的用途 | 首次验收 |
| --- | --- | --- |
| IDF-DS 固定翼开放基准 | **首选真实重复航线**，从 Pixhawk ULog 开始。论文记录 240 架次，两套飞控，PX4 示例 GPS 位置 5–10 Hz，本地位置估计 10–100 Hz。重复盘旋与速度变化可打通 L1，连续段合格后进入 L2，并用跨飞行历史做 L3。 | 抽样核验实际时间戳、GNSS 解状态、独立架次数、缺测、航段时长及航迹与站点几何。本地位置属于飞控估计，和 GNSS 分别核对。论文中的重复设定不能据此估算一般任务的复用率。 [原论文](https://doi.org/10.1038/s41597-026-06716-3) · [数据登记](https://doi.org/10.5281/zenodo.16992975) |
| AU-AIR | **多旋翼或交通巡检外部对照优先候选**。公开资料确认位置、高度、IMU、速度等，先做短时 L1 与运动剖面。 | 核验连续架次、同向路线重复数和原生定位更新率，避免把视频帧率当定位采样率。合格再升入真实轨迹闭环。 [作者数据页源文件](https://github.com/bozcani/bozcani.github.io/blob/master/auairdataset.html) · [原论文](https://arxiv.org/abs/2001.11737) |
| TrajAir | **通航的重复进场结构与多机交互对照**。作者将处理后的航迹插值到 1 秒。 | 用于通航范围的 L1、复用结构和交互分析。0.5 秒误差评估不以插值的 1 秒数据作高频真值，也不把载人航空复用率作低空无人机任务的总体比例。 [原论文](https://arxiv.org/abs/2109.15158) |
| 多视角无人机跟踪 | **短时、高采样位置基准**。附件没有给出唯一数据集 ID，可先核验 Albl 等公开的多视角六旋翼 RTK 轨迹。 | 用同一飞行原始点与降采样版本估计角度和 3 dB 越界的插值误差。是否具备重复航线要另行检测。 [作者数据仓库](https://github.com/CenekAlbl/drone-tracking-datasets) |
| ADS-B / OpenSky | **后置**。适合大范围通航路线统计或长时域补充。 | 锁定具体产品与时间戳粒度。OpenSky 的每周公开状态向量快照例为 10 秒更新间隔。 [OpenSky 数据说明](https://opensky-network.org/data/scientific) |

- L1 用 WGS84 经纬高转站点 ENU，按飞行和日期分组。按原始采样、缺测和对准精度分层。保留坐标系、真实几何、采样时间和原始文件索引。位置真值来源为飞行记录代理，插值后的中间点精度单列。有效时长只需覆盖对应历史和未来窗口。
- L2 优先保持真实时间和运动尺度。选定站点或预先锁定虚拟站点布局，再计算角度和空地传播。180 s 服务和匹配预热需要逐段验收；不足时采用事先固定的短窗口，并重新报告预算。若将独立飞行组合进同一 TDMA 世界，标明“独立真实航迹组合的半合成多机实验”。首轮先保持原空口便于归因，再对同一航迹更换一个目标场景空地信道做独立敏感性；分别说明几何证据和射频证据。
- L3 用同一场测试的已有历史架次 0/1/3/5，数据足量时加 10。历史只能早于目标架次，跨架次记忆保留有向路线，但局部速度、进度和实时滤波状态应在新架次重新初始化。以架次和路线为统计单位；重复航线只按历史观测与既定规则识别，测试目标与历史匹配情况可事后分层。未来航点与未来真值不作为模型输入。对固定翼绕圈和多旋翼停留／绕路分别报告。
- 模型研发沿用 1,200/400/400/400 的训练、验证、校准、测试路线划分，并保持窗口同源分组。用于筛模型的离线锚点放验证折。闭环策略风险带和超参数用独立仿真验证世界选择。若已有归档测试世界已被用来改机制，确认性主结果用新的锁定世界。真实分布实验先报冻结迁移，再在有足够独立架次时另外做真实域校准。

## 5 执行顺序与退出判据

| 阶段 | 要交付 | 首次运行量和进入下一阶段的条件 |
| --- | --- | --- |
| A 端到端口径检查 | 几何稳定性探测评分、F 网格带风险、到期回退、原版可复算 | 开发世界做 1–2 个宽松和紧预算的事件对照。快速网格的风险、净吞吐在抽样配置上与事件仿真一致。起始历史和公共信道指纹一致。 |
| B 两条低成本并行工作线 | F 和 RC 的验证前沿，Chronos 原生误差接口，IDF-DS 入库样本审计 | F 先筛 3.1 ms / 1.667% 的 36 组合，再验宽松基点。Chronos 先离线重放验证锚点，看分数是否随时域和输入变化，实际参与决策。IDF-DS 抽两种任务中的数个架次。 |
| C 验证小闭环 | F、IMM、P、RC、C-native、CR-G 加最多两个通过离线筛选的模型 | 两工况 × 10 个验证世界 × 6–8 臂，约 120–160 个运行，F 搜索和额外消融另计。主要工况仍用 3.1 ms / 1.667%，3.1 ms / 5% 为宽松参照，9.3 ms / 5% 作为下一档敏感性。若两边没有共同风险带，前沿本身即为结果。 |
| D 冻结确认 | 主图同风险吞吐，模型表的离线—闭环—时延关联 | 一个主工况 × 30 个新世界 × 6–8 臂，即单种子约 180–240 个运行。随机训练臂以 3 个训练种子确认，固定确定性策略可复用。世界和种子相关结构保留，避免把窗口或种子当额外独立世界。宽松参照可以分批跑。 |
| E 真实轨迹与无线敏感性 | 固定翼重复路线 L1/L3，通过验收后做 L2，按需补一档空地信道和延迟回灌 | 复用同风险主实验的 F 和 RC，再带 1–2 个有效模型。预先锁定独立架次、站点和路径损耗参数。按同一物理世界成对报告指向、SINR、吞吐。结果为真实轨迹驱动的半合成闭环。 |

时钟以小闭环预跑时单场中位数和 p95 壁钟估算。训练、概率预测采样与调度事件循环分开计时。对现有程序作裸 IMM、RC 及高级模型各自执行路径的延迟测量，把模型更新错过可执行期限的时长纳入闭环后再作效率结论。阶段 C 前不使用报告中的极端实测值推算总时长。
