# 双时间尺度 MPC 平台使用手册

## 1. 第一次运行

在 PowerShell 中执行下面两条命令。新目录会保存本次训练、仿真、日志和结果，已有演示保存在 runs/demo。

~~~powershell
cd 'D:\低空论文\routeclock_mpc'
.\start.cmd all --workers 4 --out runs/my_first
~~~

all 会依次生成独立场景、训练及校准概率模型、运行四种控制策略、生成结果报告，并从已保存账本再次复核。第一次准备世界和预热轨迹需要一些时间。终端每生成一个场景、每完成一部分闭环都会打印进度。--workers 控制数据准备阶段的进程数，闭环策略按顺序运行。

已经完成的示例可立即打开：

~~~powershell
Get-Content -Encoding utf8 'runs/demo/结果报告.md'
Import-Csv 'runs/demo/network_results.csv' | Format-Table mission,policy,Mbps,observations,sensing_pct,worst10_Mbps
~~~

## 2. 看进度、暂停和继续

另开一个 PowerShell 窗口，进入同一平台目录，执行：

~~~powershell
.\start.cmd status --out runs/my_first
Get-Content -Encoding utf8 runs/my_first/progress.jsonl -Tail 5 -Wait
~~~

第一条显示最近状态，第二条会持续刷新。关闭看日志的窗口不会影响主进程。在主窗口按 Ctrl+C 可停止运行；重新运行相同的 all 命令即可继续。恢复粒度是整个数据场景、训练模型和“场景 × 策略”的闭环。正在计算但还未写下完成标志的那一场策略会从公共预热起点重新运行。模型与场景均存放在所选输出目录，可在后续阶段直接使用。

## 3. 分阶段运行和检查

~~~powershell
.\start.cmd prepare --workers 4 --out runs/staged
.\start.cmd train --out runs/staged
.\start.cmd simulate --out runs/staged
.\start.cmd report --out runs/staged
.\start.cmd verify --out runs/staged
~~~

完成标志是每个策略目录中的 metrics.json，它在计划和账本都写好之后产生。若希望使用同一批场景与同一模型实际重跑全部策略：

~~~powershell
.\start.cmd simulate --rerun --out runs/staged
.\start.cmd report --out runs/staged
.\start.cmd verify --out runs/staged
~~~

--rerun 会替换这个输出目录下的场景策略结果。要保留两份结果，使用新的 --out。不同配置使用不同目录；已有目录的后续命令会默认读取其中的 config.json。status 可在运行过程中执行。

## 4. 到哪里查什么

|文件|建议先看什么|
|---|---|
|结果报告.md|四种策略的平均净吞吐、观测开销、最弱用户服务、公平性、波束损失和预测概率质量。|
|network_results.csv|按同一 mission 逐场比较。Mbps 为整段仿真服务时间上的净吞吐，observations 为实际观测次数，expired_s 为分给过期预测的时间。|
|risk_quality.csv|查看 1、2、5、10 秒的真实累计失效率与预测均值。Brier 越小越好，和仅按年龄估计的基线比较。|
|risk_test_编号.csv|某个发布时间 origin、某架 uid、某个预测时长 h 的模型概率 prob、年龄基线 age_base 与事后首次越界标签 event。|
|scene_编号/策略/plans.csv|每个慢层决策的计划序列。编号从 0 开始，-1 表示等待、感知时间留给通信。多步方案的后半段会被下一次滚动优化更新。|
|scene_编号/策略/ledger.csv|每个快轮、每架机一行。看 observed、age_mid_s、p_route_failed、beam_y/z、pointing_az_deg/el_deg、data_s、delivered_Mbit 和 debt_before_Mbit，可以还原决策与账本。|
|verification.json|按落盘数据重算的闭环数、快轮数、最大时钟误差。|
|config.json、training.json、risk.pkl|本轮实际配置、训练/校准规模、已训练模型。train/cal NPZ 和 test PKL 是本轮的输入缓存。|

例如，查看 0 号场景中联合 MPC 的第 30 个快轮（编号从 0 开始）：

~~~powershell
Import-Csv 'runs/demo/scene_0/joint_mpc/ledger.csv' |
  Where-Object { $_.step -eq '30' } |
  Format-Table uid,observed,p_route_failed,beam_y,beam_z,data_s,delivered_Mbit
~~~

超过 10 秒的整段不再获得模型的有效预测，过期部分计零。若某数据窗口跨过边界，仍结算有效部分；中点已过期时 p_route_failed 为空，方向列保留实际有效段使用的指向。账本中的 delivered_Mbit 是物理链路按块误码率计算的期望交付量。

## 5. 调参数与正式实验

复制 configs/demo.json 为新文件，编辑后指定它。以下是最影响结果的参数：

|参数|含义|
|---|---|
|uavs、test_ids|测试网络规模和独立网络编号，同编号各策略复用相同物理世界。|
|training_uavs、train_ids、cal_ids|训练和校准的航线规模。三种数据有不同随机命名空间；若要新一批测试航线，应更换 test_ids。|
|warmup_s、steps、dt|预热时长、服务快轮数、每轮秒数。steps × dt 为总服务时间。默认观察和通信在预热后开始计分。|
|sensing_budget|服务期可用于感知的时间比例。快轮上限为一次观测。若 dt 大于“单次观测耗时 / 预算”，即使每轮都感知也用不满预算。可在相同 dt 下比较 1%、2%、5% 三档。|
|slow_every、slow_horizon、search_width|间隔多少快轮重算观测、向未来看多少快轮、每一深度保留多少候选计划。slow_horizon 至少应覆盖 slow_every。|
|fast_horizon|通信时间线性规划向前看的快轮数。时域用轮数配置，报告物理时间时乘 dt。|
|min_airtime_fraction|所有飞机均分的保底通信时间占比。设为 1 时所有飞机平分可用数据时间，适合检查动态时间分配的贡献。|
|target_network_mbps、deficit_weight|总软服务目标及欠账惩罚强度。各机平分目标、满缓冲发送。两者影响总吞吐与弱用户服务的取舍。|

正式配置已写好，16 架无人机、180 秒预热、每场 2904 × 0.062 = 180.048 秒服务，30 个新测试场景、四种策略：

~~~powershell
.\start.cmd all --config configs/formal.json --out runs/formal --workers 4
~~~

该配置会产生 120 条完整闭环、约 558 万行逐机通信账本，同时保存物理轨迹缓存。建议使用持续可写的本地磁盘。可以先复制正式配置，只留一个 test_id 以估算本机长场景的耗时与磁盘占用，再在新目录启动整批。已交付结果来自小规模演示。

## 6. 环境、迁移与测试

本地验证环境为 Windows、Python 3.12.14、NumPy 2.5.4、SciPy 1.18.1、scikit-learn 1.9.1。start.cmd 优先使用平台目录内的 .venv，其次尝试此工作区已有虚拟环境。CPU 足以执行当前路径，启动和模型计算不需要下载基础模型权重。复制到另一台机器时，应带上 routeclock/、mpc/、assets/ 和 configs/。用下面方式建立独立环境：

~~~powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start.cmd all --out runs/local
~~~

Linux 下使用相同依赖，直接运行 python run.py all --out runs/local。Windows 工作区运行回归测试的命令如下，若使用自己的虚拟环境则把解释器改成 .\.venv\Scripts\python.exe。

~~~powershell
..\routeclock_platform_20261113\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

若出现缺少模型或场景文件的错误，运行该输出目录的 all 即可依赖顺序补齐。若出现概率训练集没有两种事件的错误，增加独立训练场景。运行阶段、异常和成功完成时间记录在 progress.jsonl。

## 7. 随平台交付的实跑记录

本次使用本地 CPU，模型训练使用 3 个独立训练网络的 312 次预测发布，概率校准使用另 2 个网络的 208 次发布。随后在 2 个独立 16 机场景中分别运行四种策略。每场先积累 180 秒历史，再运行 192 个 62 毫秒的快轮。8 条完整轨迹控制闭环的 1536 个快轮已逐轮核查，时间守恒最大误差约 6.94×10⁻¹⁷ 秒。示例输出约占 62 MiB。

联合 MPC 在两场分别达到 1057.66 和 1348.02 Mbps，轮询观测加同一快层分别为 1019.52 和 1341.55 Mbps。两场平均提高 22.30 Mbps，感知占时从 5.00% 降到 1.45%。代价是可传时间中超过 3 dB 损失的比例从 0.85% 升到 2.08%；若研究需要同等失配率比较，应另在独立验证集上选取匹配工作点。10 秒风险概率的 Brier 比仅按年龄预测更低，1 秒风险被高估。两场用于验证代码、机制和结果的可解释性，正式配置尚待运行。

7 项本地回归测试已通过。另用 1% 预算验证了稀疏观测时钟和断点恢复：20 个快轮内轮询只获得 4 次观测机会；人为标记一个未完成场景后，续跑复现了相同的逐机账本。
