# 从空服务器训练、保存模型、再独立评估

## 准备环境

将 routeclock_server_full.tar.gz 上传至服务器后执行：

~~~bash
tar -xzf routeclock_server_full.tar.gz
cd routeclock_server_full
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
~~~

源码包自带物理场景生成器、训练和测试代码、完整配置和单元测试。初次安装 NumPy、SciPy、scikit-learn 和 LightGBM 需要能访问软件源或已有的离线 wheel。Linux 精简镜像若导入 LightGBM 时提示缺少 libgomp.so.1，需要系统的 OpenMP 运行库（如 Debian/Ubuntu 的 libgomp1）。第一次安装好依赖后，训练和仿真无需下载模型。多进程用于生成独立网络，数值模型与 MPC 均在 CPU 上运行。

## 先小规模跑通

~~~bash
python run.py all --config configs/smoke.json --out runs/smoke --workers 4
cat runs/smoke/verification.json
cat runs/smoke/结果报告.md
~~~

smoke 为 4 机短验收；demo 为 2 个 16 机场景、4 个策略；formal 为 30 个 16 机场景、每场约 180 秒服务。各配置自行生成全部所需样本。

## 服务器正式使用：先训练，再运行

~~~bash
python run.py train --config configs/formal.json --out runs/train_formal --workers 4
python run.py simulate --config configs/formal.json --models runs/train_formal --out runs/eval_formal --workers 4
python run.py report --out runs/eval_formal
python run.py verify --out runs/eval_formal
~~~

train 在空目录只生成训练和校准场景。训练成功的标志是 models.json 已写入；它包含三个组件的 SHA-256。模型可单独搬到另一台机器：复制 gate.json、error_tube.pkl、risk.pkl、models.json 四个文件到同一目录；测试时用相同软件版本，--models 指向该目录。simulate 会生成指定配置的测试场景并加载三个已训练组件。可复制 formal.json 修改 test_ids 后用另一个 --out 测新航线，原训练无需重来。--models 使用的是模型目录，--out 使用的是当前实验的输出目录。

需要合并操作时，all 在同一目录准备数据、训练、仿真、生成报告并复核。prepare 可提前只生成原始输入。命令中未指定 --config 时，已有运行目录会读取自己的 config.json；新目录默认 demo 配置。

## 后台运行与进度

~~~bash
mkdir -p logs
nohup python -u run.py train --config configs/formal.json --out runs/train_formal --workers 4 > logs/train.log 2>&1 &
tail -f logs/train.log
~~~

另一个终端可执行 python run.py status --out runs/train_formal。训练完成后同样可以 nohup 启动 simulate。progress.jsonl 保存场景生成进度、当前训练阶段、闭环策略和当前快轮。status.json 保存最后的状态。训练被打断可使用原命令，已完成的场景文件会复用；模型组只在全部训练成功并写入指纹清单后才可加载。仿真按“网络 × 策略”保存，未完成的该条闭环重新计算。若只是要用当前模型实际重跑闭环，加 --rerun。改变配置或更换模型时使用新的输出目录。默认同时只允许一个进程写同一个目录。

## 输出怎么看

|文件|用途|
|---|---|
|gate.json、training.json|查看门控标准化参数、16 个特征的系数、截距、优化是否收敛，以及各模型训练样本数。|
|error_tube.pkl、training.json|保存实际拟合的 LightGBM、误差管校准因子及各独立校准网络的分数。|
|risk.pkl、models.json|失效概率及条件速率模型；门控、管、风险模型必须匹配本轮指纹。|
|tube_quality.csv|独立测试发布上两轴联合覆盖概率，以及方位和俯仰的平均半宽（度）。|
|risk_quality.csv|分时长的首次失效概率、实际发生比例和 Brier 分数。|
|scene_编号/策略/ledger.csv|逐机实际观测、门控权重 route_weight、两轴管半宽 tube_az_deg / tube_el_deg、束宽期限 beam_deadline_s、发送窗口起始年龄 age_at_start_s、分到的时间和有效 Mbit。|
|scene_编号/策略/plans.csv|慢层每次优化得到的观测序列。-1 表示空出本轮用于通信。|
|network_results.csv、结果报告.md|按独立网络和策略查看净 Mbps、感知占时、最差用户服务和实际波束损失。|
|evaluation_models.json、verification.json|复查闭环用的是哪一组模型，以及时钟、感知预算、束宽期限和通信账本是否一致。|

例如要确认“误差管真的限制了发送”，选 ledger.csv 中的任一行。允许的有效秒数应为 max(0, min(data_s, beam_deadline_s − age_at_start_s))。剩余时间列在 expired_s，按零比特结算。期限为 -1 表示该波束连发布点的几何门限都未通过。verify 会逐行重算。

## 调整规模

训练、校准和测试按 gate_ids、train_ids、tube_cal_ids、cal_ids、test_ids 五个独立命名空间划分。调整 tube_alpha 时要留足独立校准网络；目标 90% 时至少 9 个，正式配置默认 30 个。正式长场景会写出数百万行账本，建议先用一场估算磁盘和耗时。单机训练历史、通信图样、初始速度和测量噪声设置见 configs/research.json。运行单元与集成测试用 python -m unittest discover -s tests -v。需要完整 demo 缓存的集成测试在执行 demo 后可全量运行。
