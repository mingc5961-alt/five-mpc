# RouteClock 完整服务器包

在服务器终端进入解压出的 `routeclock_server`。本页命令都从这里执行。以 Python 3.12 和带 CUDA 的 PyTorch 为运行环境。若服务器镜像已有 GPU 版 PyTorch，可以直接用该环境，或者用这个解释器创建带 `--system-site-packages` 的 venv。包内提供两个预训练权重；安装 Python 依赖需要访问软件源。安装后程序从包内离线读取权重。TabPFN 回归权重供已获授权的实验账户使用。

~~~bash
python --version
python server.py verify
python -m pip install -r requirements-linux.txt
python server.py gpu
~~~

## 先测 RTX 3060

同一张卡依次运行下列三项。第一个命令分别测纯 Chronos 与带路线的 Chronos，另两项分别检验局部特征和完整特征。每份 JSON 保存首次和重复调用时间、峰值显存；输入为测速专用，结果不用于论文准确率。

~~~bash
python server.py profile chronos --repeat 2
python server.py profile tabpfn --features 16 --repeat 2
python server.py profile tabpfn --features 63 --repeat 2
cat routeclock_five_20261115/runs/day1/*.json
~~~

## 训练与运行五模型实验

该流程比较 IMM、纯路线、门控融合、纯 Chronos-2、带路线的 Chronos-2。每个中心有各自的误差头。通信端采用该实验配套调度器。用已有先导模型可直接做端到端测速。

~~~bash
python server.py five matrix
python server.py five timing --bundle runs/five_pilot/results/bundle.pkl
~~~

若要先生成一条真实长历史训练航线，使用 `python server.py five generate --split train --start 0 --stop 1`。正式实验按以下顺序进行。命令的相对参数路径由入口按相应子项目解析。

~~~bash
python server.py five generate
python server.py five train --head lightgbm --seed 7
python server.py five train --head tabpfn --seed 7
python server.py five network --block main --bundle runs/five_formal/lightgbm_7/bundle.pkl
python server.py five summary
~~~

正式 2400 条单机任务由代码从固定种子生成；完整网络实验不作为现成结果交付。分片、消融、复用比例与多种子命令详见 `routeclock_five_20261115/SERVER_RUNBOOK.md`。其中使用子目录原生工具时，如需直接提供模型目录，可先在包根目录执行 `source models.env`。

## 路线门控、失效风险与双时间尺度 MPC

这条实验从航线与带噪观测开始重新训练门控、LightGBM 误差管、失效概率与条件速率模型，再比较 16 机感知调度和通信分配。当前真正进入 MPC 的位置中心是路线与 IMM 的融合。Chronos 和 TabPFN 的实验入口在上一节。两个项目分别保留其数据定义、模型和调度器。

~~~bash
python server.py mpc all --config configs/smoke.json --out runs/server_smoke --workers 4
python server.py mpc all --config configs/demo.json --out runs/server_demo --workers 4
python server.py mpc train --config configs/formal.json --out runs/server_train --workers 4
python server.py mpc simulate --config configs/formal.json --models runs/server_train --out runs/server_formal --workers 4
python server.py mpc report --out runs/server_formal
python server.py mpc verify --out runs/server_formal
~~~

在第二个终端中用 `python server.py mpc status --out runs/server_formal` 查看进度，相同输出目录支持按已完成阶段/场景续跑。本次新运行的报告在 `routeclock_server_full/runs/server_formal/结果报告.md`。

## 复现“现在等待或刷新”143 个分叉

包内有原两场世界、训练好的模型、观测计划、逐机账本和已完成对照。以下命令另建输出，不覆盖原始对照。

~~~bash
python server.py paired run --workers 4 --out runs/server_paired
python server.py paired audit --out runs/server_paired
python server.py paired search --out runs/server_paired
python server.py paired summary --out runs/server_paired
~~~

结果表为 `routeclock_server_full/runs/server_paired/summary.csv`。旧的已完成对照报告在 `routeclock_server_full/runs/demo_paired_refresh/对照报告.md`。五模型目录也包含固定时隙调度、门控误切、分位数管以及其对应先导数据。前期版本 `routeclock_platform_20261113` 和 `routeclock_mpc` 保留独立源码、配置、测试与历史模型接口，主实验使用上面的两个入口。
