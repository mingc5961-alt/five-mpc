# 最终代码与设计的核对

本次交付以用户2026-11-13的要求为准：实现报告中的模型和闭环，执行本地代码验收，不以改善性能为目标调整方法。

## 数据与预测
- 世界、离线split和网络任务分开命名；Tracker只接收量测，不接收真实路线或类别。
- 多个同路段交叉候选分别传播；只有观测到的开放路段末端接续可以连接，桥段距离计入进度。
- 进度分布保留模式和匹配分支的不确定性；点估计消融同时去掉模式内与模式间进度方差。
- 谐波使用在线漂移状态空间模型；其已发布预测的兑现误差同样进入诊断。
- 无新量测时不重新拟合或重置预测原点；新量测先检查旧预测再更新地图。

## 学习与校准
- RC与I不读取闭环中未执行的Chronos预测误差。CR使用自己的专家档案。
- 门控按任务分组OOF输出训练误差头，验证用于有限选型，校准与测试分离。
- 校准每任务随机保留一个早/中/晚锚点，但其此前观测时序与相应测试协议一致。
- 60维诊断加3维查询编码，共63维；真实TabPFN-2.5回归器、4个estimators、fit_with_cache。
- A2固定中心删除档案仅影响误差头；D删除档案时门控与误差头一起重新拟合。

## 动作与记账
- 先施加“只调间隔／只调宽度”限制，再筛选Pareto候选，避免删掉受限方案唯一可用动作。
- 统一加宽按所有机共同子阵档位执行；价值调度保留各机不同宽度。
- 角域矩形转换为方向余弦外包范围，以二维联合阵列增益确定期限。
- 感知成本以3.1ms真实时长扣除，不四舍五入到20ms真值步长。
- 数据事件保存实际采用的束宽、期限、MCS、SNR和有效比特；图从执行事件读取动作。
- 末尾不足一次感知的时间仍进入数据账本；逐事件比特可重算总净吞吐。

## 审查记录
技能要求的两轮审查已执行并保留原始JSON；属于同模型家族审查。第二轮结束时仍列出的观测协议、谐波兑现诊断和节点图来源三项，由执行人随后修复并通过回归检查，未把旧审查结论改写为独立通过。

## 验收数据版本
`data/final_real` 使用最终观测协议与63维误差头输入；最终模型与闭环输出放在 `runs/final_*`。`data/local`、`data/acceptance`、`data/real_models`及早期runs保留为开发过程，不与最终验收数据混合使用。
